## New findings

### MEDIUM-1 — `.tailcat-allow` missing from `.gitignore`

The fail-closed client allowlist (`nodekey:...` credential) is not git-ignored.
`.gitignore` covers `.agent-token`, `logs/`, `data/`, and DB files, but the documented
layout puts `.tailcat-allow` at `$HOME/dispatcher-go/.tailcat-allow`
(`tailcat-serve.sh:9`, `tailcat-serve.sh:18`) — inside a normal clone location.
One `git add .` away from committing a shared-secret material.

**Fix:** add `.tailcat-allow` to `.gitignore` (root-level pattern covers the
documented install dir when it is the repo checkout).

### MEDIUM-2 — `tailcat-serve.sh` supervisor dies on non-zero tailcat exit

The script runs under `set -eu` (`tailcat-serve.sh:13`) and supervises with:

```sh
wait $pid
code=$?
```

Under `errexit`, `wait` returning tailcat's non-zero status aborts the whole script —
i.e. the supervisor exits exactly when it should restart. `code=$?` is unreachable for
non-zero exits, so the backoff/restart loop only works for clean (0) exits.

Contrast `tailcat-forward.sh:23`, which correctly guards with `|| true`.

**Fix:**

```sh
code=0
wait "$pid" || code=$?
```
